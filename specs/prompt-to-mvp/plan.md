# Plan: Create a project from an app prompt

Slug: `prompt-to-mvp` · Status: READY · Estimate: 60

## Goal
When creating a project, I describe what the app should do instead of writing a repo description. The factory writes a short repo description from that prompt and files an MVP feature issue that Copilot starts building right away.

## Source
Issue: None. Requested in chat: "use an initial prompt and let the app then create its first MVP from that prompt … it creates a description for the repo".

## Acceptance criteria
- [x] **AC1**: Given the New project form, when it opens, then it asks "What should this app do?" (optional, up to 8,000 characters) instead of a description field.
- [x] **AC2**: Given a prompt, when the project is created, then the GitHub repo description is a single-line summary (≤350 chars) generated by GitHub Models, falling back to the prompt's first sentence if the model call fails or mocks are on. The dashboard shows the description on the project row.
- [x] **AC3**: Given a prompt and a fully provisioned project, when creation finishes, then a `Build the MVP` issue containing the prompt is created and approved (queued for Copilot), and the dashboard links to it.
- [x] **AC4**: Given a prompt and a project that still needs repair (e.g. missing secret), when creation finishes, then the MVP issue is created but left awaiting approval on the project page.
- [x] **AC5**: Given no prompt, when the project is created, then no MVP issue is filed and behavior matches today.
- [x] **AC6**: Given a prompt over 8,000 characters or a non-string prompt, when posted to `/api/projects`, then the API returns 400.
